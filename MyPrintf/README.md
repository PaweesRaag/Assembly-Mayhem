# MyPrintf

A small `printf`-style formatter implemented directly in x86-64 assembly using Linux system calls.

## Overview

MyPrintf is an educational formatter written from scratch to explore how formatted output can be built from low-level primitives rather than relying on the C standard library.

The implementation scans a NUL-terminated format string, recognizes a small set of formatting and escape sequences, converts values when required, and emits output directly with the Linux `write` syscall.

## Supported Syntax

| Syntax | Behavior |
| --- | --- |
| Ordinary bytes | Written directly to stdout |
| `\n` | Emits ASCII newline (`0x0A`) |
| `\\` | Emits a literal backslash |
| `%%` | Emits a literal percent sign |
| `%d` | Converts the next command-line argument from signed decimal text to an integer, then back to decimal text |
| `%s` | Writes the next command-line argument as a literal string |
| `\xNN` | Decodes two hexadecimal digits into one arbitrary byte |

Examples:

```text
Format:  value=%d
Argument: -42
Output:   value=-42
```

```text
Format:  opened %d files and skipped %d
Arguments: 7, 3
Output:   opened 7 files and skipped 3
```

```text
Format:  byte=\x2a
Output:   byte=*
```

Strings supplied through `%s` are treated as data. Characters such as `\\` and `%` inside a `%s` argument are copied literally and are not interpreted as formatter syntax.

## How It Works

The formatter maintains two pieces of state:

- `r12`: current position in the format string (`argv[1]`)
- `r13`: byte offset of the next formatting argument, starting at `argv[2]` (`24` bytes from the initial `rsp`)

The main loop examines one byte at a time.

1. A normal byte is passed directly to `write(1, ..., 1)`.
2. A backslash starts an escape sequence. The formatter recognizes `\n`, `\\`, and `\xNN`.
3. A percent starts a format marker. The formatter recognizes `%%`, `%d`, and `%s`.
4. `%d` calls the custom `atoi`, converts the resulting integer with the custom signed `itoa`, and writes the generated bytes.
5. `%s` walks the supplied string until its NUL terminator to determine the length, then writes the whole string.
6. `\xNN` converts the two ASCII hex digits into numeric nibbles, combines them with `(high << 4) | low`, and writes the resulting byte.

## Low-Level Components

### `atoi`

Converts an ASCII decimal string to a signed integer. It supports an optional leading `-` and accumulates the value using:

```text
value = value * 10 + digit
```

### `itoa`

Converts a signed integer back into decimal text. It repeatedly divides the magnitude by 10, pushes the remainders onto the stack, and then pops them in reverse order so the output digits appear left-to-right. Negative values receive a leading `-`.

### Hex decoding

The `hex_digit` routine converts ASCII characters `0-9`, `A-F`, and `a-f` into 4-bit nibble values. The two nibbles are then combined into one byte.

## Syscall Interface

Output is performed directly through Linux `write`:

```text
RAX = 1   syscall number
RDI = 1   stdout
RSI = buffer
RDX = byte count
```

The program terminates through `exit`:

```text
RAX = 60  syscall number
RDI = status
```

No C runtime or standard-library `printf` implementation is used.

## How This Differs From Standard `printf`

MyPrintf is intentionally much smaller than a production C library `printf`. It is not intended to replace libc formatting functionality.

| Capability | MyPrintf | Standard `printf` |
| --- | --- | --- |
| Literal output | Yes | Yes |
| `%d` | Yes | Yes |
| `%s` | Yes | Yes |
| `%%` | Yes | Yes |
| Multiple `%d` / `%s` values | Yes | Yes |
| Custom `\xNN` byte escape | Yes | Not a standard `printf` format feature |
| Custom `\n` / `\\` interpretation | Yes | Normally handled by the C source/compiler before `printf` receives the format string |
| Integer width/precision/flags | No | Yes |
| `%u`, `%o`, `%x`, `%X` | No | Yes |
| Floating-point formats | No | Yes |
| `%c`, `%p` and many other conversions | No | Yes |
| Locale and advanced formatting | No | Yes |
| Buffered stdio integration | No | Yes |

The interesting difference is implementation rather than feature count: MyPrintf exposes the mechanics of formatting directly in assembly—string scanning, pointer management, register usage, integer conversion, stack-based digit reversal, byte decoding, and raw Linux syscalls.

## Why Build It?

This project is primarily an x86-64 systems-programming and reverse-engineering exercise. It demonstrates the progression from raw byte output to a small parser with multiple data types and escape mechanisms.

The project reinforces:

- x86-64 register and pointer management
- NUL-terminated string traversal
- Linux syscall conventions
- ASCII and hexadecimal byte manipulation
- Signed integer parsing and formatting
- Stack usage for temporary digit storage
- Basic parser/dispatcher design
- Separation between format-string syntax and user data

## Build

The source is written for GNU `as` using Intel syntax and can be built as a standalone Linux executable:

```bash
as -o printf.o printf.s
ld -o printf printf.o
```

Run it with a format string followed by any required values:

```bash
./printf 'value=%d' -42
./printf 'opened %d files and skipped %d' 7 3
./printf 'byte=\x2a'
```

## Project Status

This is a deliberately focused educational formatter rather than a full libc-compatible implementation. Future extensions could add additional integer formats, character output, width/precision handling, or a more formal argument-validation layer.
